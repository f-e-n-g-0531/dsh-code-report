# 单次摘要：模型输入、覆盖范围与归档

本文描述 v0.10.0 的 `single-request` 实现，不代表正式发布已完成或已安装的 DSH 已更新。使用入口见[使用说明](<../README.md>)；历史验证仍保留在[验收记录](<ACCEPTANCE.md>)。

## 默认与请求边界

- [宿主](<../src/host.mjs>)默认计划器固定 `strategy:"single-request"`，输入预算默认 64000 字节，重规划范围 4000–64000；UI 没有切换 full 策略的选项。预算是含提示、JSON 包装及路由预留的 UTF-8 保守估算，不是 token 或实际网络请求长度。小预算可能连必要统计都放不下，规划会失败。
- 一次明确确认生成恰好一份模型 payload；插件不自动拆分，不在同次生成中派发第二次 `llm.stream`，失败不自动重试。显式重试须重新确认且可能再次计费。不能用插件调用数推断供应商计费或保证底层适配器没有重试。
- [库级计划器](<../src/analysis.mjs>)仍默认 `strategy:"full"`、24000 字节，并支持全量分片；这不是当前宿主/UI 默认。历史 full 测试不能替代单次摘要验收。

## 完整本地清单不等于模型全文

[摘要构造器](<../src/single-request.mjs>)先解析完整已采集差异及上下文，建立本地路径、状态、字节、哈希、范围及来源清单，再选取有限模型证据：

1. 每个项目的必要统计、固定端点与清单哈希先进入请求。必要统计装不下时拒绝规划，不静默删项目。
2. 各仓库及单独上下文通道轮转分配剩余预算；文件按生成物标志、路径/扩展名优先级与路径排序。接口目录、头文件、源码、配置等优先级只是确定性启发式，不是完整依赖分析或语义重要性判断。
3. 文件元数据也受预算约束，完整清单中的部分路径可能完全没有文件专属证据发给模型。被选文件仅可能附带差异块或上下文的有限前缀，单片前缀最多 1024 UTF-16 单元，还可能因预算更短；不是完整文件，也不是所有 hunk。
4. 生成物通过扩展名等路径模式识别，不读取其用途作语义判断；识别为生成物或二进制的正文不发送，生成物元数据也可能未入选。没有被识别成生成物不证明它一定是源码。

发送前核对 `fullManifestFiles`、`sentFileCount`、`sentTextFileCount`、`omittedFileCount`、`generatedFileCount`、上下文计数与 `sentSourceBytes`。`originalSourceBytes`/`decodedSourceBytes` 是解码后 UTF-8 文本口径，包含上下文时也计入上下文，不是远端原始传输字节。`processed`、`cited` 只统计已发送摘要证据；不能称为全部代码已理解。未发送内容无法支持“没有接口变化”“无风险”或完整跨仓调用关系结论。哈希与合法引用只证明身份/定位，不证明结论正确。

## 主报告与完整证据保存

[报告生成器](<../src/report.mjs>)在单次摘要模式下输出固定端点、哈希、本地文件清单及文件证据/正文发送标记，不内嵌全部 diff。成功的模型报告正文采用短数字引用，不在每条结论前重复“分片 1”或原始证据 ID；两份默认折叠的技术附录保留完整清单、实际发送的摘要/原文片段正文、证据 ID、source 与 block 哈希及 UTF-16 字符起止偏移；偏移不是源码行号或字节位置，合成统计也不等于原文件。默认计划器即使规划失败也使用本地 compact manifest，不回退嵌入巨量 diff；库级自定义 full 调用另论。保留已发送证据便于核对，不把它扩展为全部差异归档。

完整 snapshot 只保存在宿主预览内存中：开始分析前 TTL 为 10 分钟，重规划不续期；释放、淘汰、重启都会丢失，成功生成会删除预览。报告恢复缓存只保留报告，不等于恢复完整证据。当前 UI 没有完整快照自动落盘或导出按钮；需要证据归档时，必须在释放或过期前由操作者通过明确授权的本地流程另存原始快照/差异，并核对固定端点与哈希。只下载摘要 Markdown、保存配置或保留哈希不能重建原文。
