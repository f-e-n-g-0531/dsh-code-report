# 正式发布与失败恢复

面向维护者。使用者只需阅读[用户指南](<../README.md>)，不需要 npm token 或 CI 配置。

## 版本规则

每次改动验证通过后提交、推送并发布正式版，无需额外提醒。采用 vX.Y.Z：X 大版本、Y 小版本、Z 修复；升级 X 时 Y/Z 归零，升级 Y 时 Z 归零。已推送的公开标签不移动，失败版本保留并注明原因。

发布不授权自动修改当前 DSH 安装环境或重启宿主。测试失败先修复，不跳过门禁。

## 触发与制品来源

普通分支推送、拉取请求不触发 CI。匹配版本的标签推送触发发布；手动 workflow_dispatch 默认只测试，在版本标签上明确 publish=true 才发布。

1. 标签必须与清单版本一致，任务检出触发的提交。
2. Ubuntu / Windows × Node 22 / 24 四组任务安装锁定依赖，构建客户端、运行临时 Git/SVN 和模拟宿主/模型测试、打包并做生产依赖隔离安装。
3. 发布任务只下载同一次运行中 Ubuntu / Node 24 的已测 tgz，复核 SHA-256、再次隔离安装，并保留原始制品。不在发布任务重新打包。

Windows SVN 来自校验过 SHA-256 的工具归档，UTF-8 manifest 修改仅针对 CI 临时工具，不修改用户机器。

构建会生成 `dist/build-provenance.json`，记录版本、相对路径输入哈希及客户端字节哈希；不包含源码正文、时间戳或本地绝对路径。`verify:package` 只校验并打包，不自动重建：同版本源码、依赖锁或构建脚本变化后，旧客户端会被拒绝，需先运行 `npm run build`。隔离安装会检查内嵌版本与哈希，并执行已安装客户端 factory 和侧栏注册；这仍不是 DOM 或真实宿主验收。

## 发布顺序与安全门禁

| 阶段 | 行为 |
| --- | --- |
| npm 首次查询 | 元数据 404 为 absent；元数据存在、tgz 404 为 pending；包可读为 ready |
| 首次发布 | 只有首次 absent 才调用 npm publish，使用同一 tgz；NPM_AUTOMATION_TOKEN 作为 NODE_AUTH_TOKEN 注入 |
| 传播等待 | pending 或已执行 publish 后，只查询不重发。确认版本存在后，即使后续元数据退回 404 也不再发布 |
| 内容核验 | 下载包与原始 CI 制品 SHA-256 一致才继续；权限、服务错误或字节不一致立即失败，不当作不存在 |
| GitHub | 再核验 npm 和远端标签提交；已有资产先检查，只补缺失；新建草稿全部资产下载核验后公开 |

发布、独立 npm 核验和 GitHub 前置检查使用同一等待逻辑：每阶段最多 60 次、间隔 10 秒，另加请求耗时；发布任务总预算 45 分钟。超时不表示未发布，更不能因此换包重传。

发布脚本按 SHA-256 比对内容，不覆盖不一致的既有 npm 版本或 GitHub 资产。GitHub 已有正式 Release 的缺失资产可以补齐；新 Release 先建草稿，防止不完整资产直接公开。

## 部分成功后的恢复

优先在**原 Actions 运行**重跑失败的发布任务，复用该运行保留的原始制品。

- npm 已接收但元数据或包暂时不可见：等待传播；超时后先查远端，不盲目重新 publish。
- npm 已存在且字节一致：跳过发布，继续核验并恢复后续步骤。
- GitHub 上传部分成功：重跑先比对已有资产，缺失才上传；不删除或覆盖不一致内容。
- 字节不一致：停止。查明制品来源，回到原运行保留的制品；不移动标签，不覆盖 npm。
- 原制品已过保留期：不能用新包冒充原包，应停止恢复并另行决定新版本发布。

新的 workflow_dispatch 会重新执行测试和打包，不等同于复用原制品；如果与已发布字节不同，必须失败。网络失败可能发生在远端已完成写入之后，先查询再重试，不在同一操作里盲目重放写请求。资产下载仅接受一次跳转到 `https://release-assets.githubusercontent.com`，不向下载域转发 API 凭据；其他 API 请求拒绝重定向。GitHub HTTP 适配器不会自动重试创建、上传或公开请求；返回结果未知时停止，原任务重跑会先完整查询 Release 与资产分页，再校验已有字节。分页未完成、重复资产或下载校验不一致均停止，不公开草稿。

## 本地质量检查

- `npm run check:static`：仅解析 JavaScript / JSX 及 JSON，不产生构建文件；不等同于类型检查或完整 lint。
- `npm run test:coverage`：构建后运行 Node 测试及实验性覆盖率统计，用于建立行／分支基线，不把用例数当覆盖率。
- `npm run test:browser`：构建后运行独立浏览器夹具，使用真实 React DOM 与模拟 DSH 服务；不连接或替换日常 DSH 页面。浏览器准备和真实宿主清单见[验收指南](<ACCEPTANCE.md>)。
- `node --test test/release-transport.test.mjs`：离线验证 HTTP 适配层的标签解引用、分页、写后断线恢复和资产损坏，不访问 npm／GitHub，不执行真实发布。

上述命令可在本地执行，CI 触发方式仍为标签或手动；浏览器与覆盖率不自动加入每次发布矩阵。

## 发布前后清单

更新清单及锁文件中的版本、用户指南版本示例和本版说明。发布说明要列出实际变化、验证结果和仍未验收的内容，不写聊天过程或未经证明的修复效果。

~~~sh
npm ci --include=dev --ignore-scripts
npm run check
npm run verify:package
npm run test:install
git diff --check
# 提交修改后，用本次未使用的版本替换 X.Y.Z
git tag vX.Y.Z
git push origin main
git push origin vX.Y.Z
~~~

等待四项测试及发布任务结果，再从公开 npm 与 GitHub 下载包、核对字节和 SHA-256，记录提交、标签及流水线。若发布中断，报告真实状态，不把推送标签称为发布完成。

## 验收声明

隔离安装检查使用模拟宿主，不是当前 GUI 安装验收。真实 GUI、原生自更新和真实模型端到端未验收时，文档必须保留说明。此前页面退出反馈未确认根因，不能把更新防护描述为崩溃已修复。发布后不自动安装或重启当前 DSH。
