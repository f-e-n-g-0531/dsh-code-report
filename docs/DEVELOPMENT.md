# 开发指南

本文面向需要修改插件或运行测试的开发者。只想使用插件，请看 [使用说明](<../README.md>)。

## 准备环境

需要 Node.js 22 或更新版本、npm、Git。运行 SVN 集成测试还需要 svn 和 svnadmin 命令。测试会创建临时仓库，不使用你的业务仓库。

## 安装依赖与检查

在项目根目录执行：

~~~sh
npm ci --include=dev --ignore-scripts
npm run check
npm run verify:package
npm run test:install
~~~

- check：编译界面并运行自动化测试。
- verify:package：检查安装包包含的文件，生成安装包及 SHA-256 校验值。
- test:install：在临时目录安装刚生成的包，检查服务端入口与客户端加载。

安装测试使用模拟 DSH 接口。测试通过不表示已在真实 DSH 页面中验证，也不表示真实模型分析质量通过验收。这些命令不会安装到你的日常 DSH 环境。

## 前后端如何分工

保持一个 npm 安装包、两个运行入口，不另外启动 HTTP 服务：

- 浏览器前端：显示配置、报告和进度；通过插件 RPC 调用后台。只在用户明确确认后调用 DSH 原生更新接口。
- DSH 后台：读取仓库、保存预览、调用模型；不接收前端提供的任意工作区根目录。
- 共享协议：只放通道名称和版本号等常量，不依赖 Node 或 DSH 服务。

界面显示构建时版本，后台版本在模块首次加载时固定。主页面验证包身份、版本和协议，一致后才执行首次自动发现；不一致禁止业务请求并提示手动重启。刷新浏览器不会重载后台模块。更新控制器在插件实例内独立于页面组件保存状态，不保证跨刷新或模块重载持久化。

当前宿主的 pluginManager.installBundle 对已安装依赖返回 restart-required。更新通过原生服务完成，不绕过宿主的兼容性、安装回滚和生命周期处理，不批准额外构建脚本，不关闭/重启宿主。安装版本固定，保留原启用状态；网络断开时结果标为未知，不声称成功或自动重试安装。

这次是代码与职责分离，不是两个独立发布的包，也不承诺后台热更新。真正独立的分析服务需要另行设计模型访问、鉴权和端口管理，目前未引入。

## 仓库发现与版本端点

首次通过后台验证后只检查工作区根目录和一级子目录，不进入更深目录。跳过隐藏、常见缓存及链接目录；最多 500 个项目、100000 个目录，约 120 秒循环预算，单条命令另有超时。发现读取本地目录和 SVN 工作副本信息，不枚举远端分支。合并保留原输入与勾选，新项目不选中；扫描不会清除已有报告。

Git 支持本地分支、SHA 和标签。SVN 两侧必须有仓库相对分支路径和数字版本（可带 r 前缀），分别用各自固定 peg/operative 端点比较，验证 UUID 和仓库根一致，不允许任意 URL。报告保留两侧分支与版本来源。

## 资源限制

一次最多 12 个项目，附带源码最多 20 个文件，单文件 128 KiB；采集结果 JSON 限制 1 MiB。单个命令输出限制 4 MiB，超时 60 秒；单次执行请求超时 240 秒。采集大小超限报错；扫描预算超限返回部分结果并提示，两者不能混为一谈。模型输出（含推理增量）最多 256 KiB、请求 maxTokens 为 8192，不代表所有模型都接受相同输入。

预览保存在宿主内存中，最多 16 项，发送前创建满 10 分钟即拒绝。容量不足可淘汰最旧未分析项，离开或替换时前端尝试释放；进行中分析不因清理被删除。成功后删除预览；失败仅在未过期且仍存在时可重试，可能再次计费。报告不持久化，配置保存不包含报告。

## 安全与验收边界

命令使用有界输出、严格 UTF-8 解码。Git 清除继承 GIT_* 后设置固定参数，禁用 replacement refs、外部 diff/textconv、颜色和子模块忽略；不表示隔离了所有仓库配置。源码同时检查输入与解析目标的工作区边界及敏感路径，但不构成完整密钥扫描或所有文件替换竞争的防护。模型派发前检查取消；已发请求取消和计费由适配器与服务决定。

现有测试包含真实临时 Git/SVN 仓库和模拟宿主/模型。不能写成真实 GUI、自更新、付费模型、SVN HTTP/HTTPS 全组合均已验收。此前页面退出反馈仍无已确认根因。
