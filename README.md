# DSH Code Report · 多项目发布报告

比较多个 Git / SVN 项目的两个版本，导出中文 Markdown 报告。可以只导出本地差异证据，也可以在确认发送后，让 DSH 中配置的模型整理改动、对外接口变更、影响范围和 QA 测试建议。

**这是 DeepSeek Harness（DSH）的插件，不是独立应用。** 模型建议需要人工复核，不代表测试通过或发布批准。

> 本文对应 v0.8.1，新增 GBK/GB18030 正文解码；本版已完成 232 项本地回归、29 项浏览器验证和精确打包安装检查，不沿用 v0.8.0 的通过数字。文件夹源码及取消规模硬上限的行为保持不变。正式发布及安装可用状态以 npm 与 GitHub 远端核验为准；模拟 DSH 浏览器测试不代表真实游戏版本范围、宿主、原生自更新或真实模型已验收。

## 安装与准备

- 使用可运行的 DSH；插件要求 Node.js 22 或更新的运行时。桌面版是否另需安装 Node.js，以宿主安装方式为准。
- 运行 DSH 的环境需能调用 Git；使用 SVN 项目还需能调用 svn。普通使用不需要 svnadmin。
- AI 分析需要提前在 DSH 配置模型服务。插件不提供模型服务，也不要求在本页面填写 API Key。

确认目标版本已正式发布后，优先使用 DSH 自带的“插件”页面安装 npm 包（以下为候选版本号，不代表当前已可安装）：

~~~text
@feng0531/dsh-code-report@0.8.1
~~~

也可使用已配置好的 DSH 命令行。确认当前 profile 名称后再执行；profile 是插件安装环境，不是会话名或工作区路径。例如，只有确认使用 desktop 环境时才运行：

~~~sh
dsh plugin --profile desktop add @feng0531/dsh-code-report@0.8.1
~~~

安装会修改对应环境，先备份配置。命令行安装还需满足 DSH 自身的包管理器要求。安装后保存工作，手动完全退出并重新启动 DSH，再刷新原页面。**只刷新页面不会重载旧后台。** 发布新版本不会自动升级或重启你的环境。

[GitHub 正式发布页](https://github.com/f-e-n-g-0531/dsh-code-report/releases)提供安装包和校验文件；下载 tgz 本身不等于已安装。普通用户无需下载源码或自行构建。

## 从配置到报告

### 1. 打开“发布报告”

打开带工作目录的 DSH 会话，点击侧栏“发布报告”。多个项目应位于会话工作目录内；项目位于目录外时不能直接读取。

页面先验证后台身份、版本及协议，一致后自动发现一次：**仅检查工作区根目录及一级子文件夹，不递归进入项目内部。** 点前缀隐藏、常见缓存及链接目录跳过（不按 Windows Hidden 属性筛选）。嵌套项目可手动添加。

自动发现不获取远端 Git 分支，也不扫描源码调用关系。失败后可点击“扫描 / 重新发现”重试；重新验证或更新失败解锁不会自动重扫。扫描保留已填写的项目与版本、现有预览和报告，新发现项目默认不选中。

### 2. 勾选项目，填写 A/B 分支，版本可留空

| 输入 | 填写方式 |
| --- | --- |
| 项目路径 | 相对于会话工作目录；根目录填 "."，例如 client 或 server |
| Git 分支 A/B | 版本留空时必填，使用本地已有分支，如 main、release 或 origin/release；不自动 fetch |
| Git 版本 A/B（可选） | 留空取对应分支最新提交；填写本地已有分支、标签或提交 SHA 时优先按该版本解析 |
| SVN 分支 A/B | 相对于 SVN 仓库根目录，例如 trunk、branches/release；"." 表示当前工作副本的仓库路径 |
| SVN r 版本 A/B（可选） | 留空取对应分支最新一次提交；指定历史版本支持 r1200 或 1200，不接受手填 HEAD、日期或版本范围 |

Git 可点击对应项目的“读取本地 refs”选择本地分支、标签或远端跟踪引用；只查询本地，不联网。逐行错误会标出缺失内容，重复项目须先移除。

Git 示例：A 分支填 main、B 分支填 release，两侧版本均留空，比较这两个分支各自的最新提交。也可在版本栏填写 v1.0.0、v1.1.0 比较固定历史端点。引用和所需提交、文件对象必须已在本地。报告 Git 命令禁用传输协议和按需补取对象，不自动 fetch；partial clone 等仓库缺对象时直接失败，请先在插件外自行补齐，再重新采集。远端跟踪分支可能滞后服务器。

SVN 示例：A 分支 trunk、版本 r1200；B 分支 branches/release、版本 r1250。两侧必须属于同一仓库。即使使用本地 SVN 仓库，也要勾选历史读取授权；远程仓库可能产生网络访问。

一次最多选择 **12 个项目**。路径、分支和版本逐行核对后再采集。只留空一侧时，该侧使用对应分支最新提交；A/B 是同一分支且两侧版本均留空时没有差异，不会自动改成“上一版对最新版”。采集先解析并固定 Git SHA / SVN revision，报告展示固定端点；SVN 最新提交按分支历史解析，不是直接使用全仓最新 revision。

### 3. 减少重复填写

- 搜索项目路径或勾选“仅看已选”，只改变显示，不取消隐藏项目的选择。
- 展开“批量填版本”，应用于**所有已勾选的同类型项目**，不受搜索筛选限制。默认只填空白；取消该选项才覆盖已有值。批量栏留空的字段保持原值。
- 点击“保存配置”，保存项目、选择状态、A/B 版本、标题、源码路径、提供方 ID 和模型 ID。下次同一浏览器、同一工作区打开时恢复。修改后需再次保存；“恢复已保存”会替换当前输入，使当前预览失效；旧报告保留并标为旧配置结果。

配置保存在浏览器本地存储，不写入项目、不跨浏览器同步。清理浏览器数据可能丢失配置。保存时包含此工作区的 SVN 历史访问勾选状态，恢复后会明确提示，可能允许后续 SVN 采集联网。旧版配置未保存该字段时默认关闭。不保存密码、API Key、源码正文、预览、报告或模型发送确认；**不要在输入字段中粘贴凭据**。模型发送仍需每次确认。

### 4. 按需附带源码文件或文件夹

展开“附带项目源码（可选）”，每行输入一个工作区内的文件或文件夹路径，例如：

~~~text
client/src/api.ts
client/src/components
client/CI/Env
~~~

支持直接填写目录，递归展开其中的源码文件；根目录可填 `.`。只展开明确填写的路径，不自动附带其他项目或扫描调用链；路径可来自工作区内另一个项目。目录内点前缀隐藏、敏感、依赖、构建和缓存路径、链接及非普通文件会跳过，预览的限制说明列出排除计数；隐藏判断基于点前缀，不读取 Windows Hidden 属性。显式填写敏感路径仍拒绝，不因目录支持而允许凭据文件。

普通路径补充源码取自**当前磁盘内容**，不一定属于 A 或 B，报告会单独标记。需要历史契约时，在“固定版本源码”中每行填写 `仓库路径|A或B|仓库相对路径`，例如 `client|A|src/api.ts` 和 `client|B|src/api.ts`。仓库必须已经选中；固定版本源码仍仅支持文件，不支持目录。两侧分别读取本次固定的 Git 提交或 SVN revision，不存在、符号链接、含 NUL 或无法按支持的编码解码时会失败，不会改读磁盘。工作区与固定版本源码的路径条目和实际文件数量不设固定规模上限。

源码按完整文件优先严格 UTF-8 解码，失败后尝试严格 GB18030（兼容 GBK），无需手动选择编码；工作区文件、目录展开文件和固定 A/B 源码使用同一规则。含 NUL、UTF-8 与 GB18030 均无法解码或无法读取时，整次采集失败，不静默跳过或截断。单文件大小、证据总量、源码目录展开的条目数、目录数和深度不设固定规模上限，仍受可用内存、操作系统与工具限制；大范围采集和报告展示可能明显增加耗时及内存。源码目录展开不同于项目自动发现，后者仍保持有限的浅层扫描范围。

Git/SVN 差异按原始 LF 字节边界逐行执行 UTF-8 优先、失败后 GB18030 的规则，兼容 UTF-8 路径头与 GBK 正文分别占行的差异。这不是完整编码检测器：同一行混合编码、同时可按 UTF-8 与 GBK 解码的歧义字节不保证识别；不会修复已有乱码或已存在的 U+FFFD，也不修改源文件。路径名单、SVN XML 等元数据仍严格要求 UTF-8。

常见敏感路径会被拦截，但这不是完整密钥扫描；发送前仍需检查密码、令牌与私人信息。

### 5. 采集并检查证据

按钮不可用时，旁边会提示后台验证状态、正在进行的任务、超出 12 项、具体项目缺失的路径或 A/B 分支；包含 SVN 项目时还需勾选历史读取授权。窄窗口下 A/B 输入栏在项目下方纵向显示，无需横向寻找。

版本差异中的 `.git` / `.svn` 内部路径在读取正文前自动排除，并在报告列出路径及覆盖限制；不是先读取再删文本。其他敏感路径（如 `.env`、密钥文件）仍阻断整个采集并提示项目和路径。附带源码不允许指定内部路径。

点击“开始执行 · 采集差异”。这一步**不调用模型**；SVN 历史读取可能访问仓库服务器。

完成后检查项目、固定版本、变更路径数、目录展开后的实际源码文件清单、来源及排除计数等限制说明，核对后才授权发送模型。报告显示源码 `encoding` 及原始字节 SHA-256（`hash`/`rawHash`），差异显示 `diffEncoding`、原始字节 `rawDiffHash` 与解码后 UTF-8 文本 `diffHash`；文本哈希不等于原字节哈希，不能用它证明未转码。此时可以下载本地证据报告，但它还没有 AI 影响分析和 QA 建议。

预览在后台内存中保存，创建满 **10 分钟**后不能再开始分析；页面显示剩余有效期，到期可重新采集。后台重启、主动释放或缓存淘汰也可能使其提前失效。修改比较输入或恢复配置会使旧预览失效，但保留上一份报告并标记为旧配置结果，仍可下载。重新采集失败或取消不会删除旧报告；成功采集展示新的本地证据，同时单独保留最近一份成功模型报告，可用“查看上一份模型报告”切换并下载。

### 6. 确认发送，让模型整理报告

在“确认分析范围”中填写 DSH 已配置的**提供方 ID**和**模型 ID**。它们是路由标识，不一定等于显示名称；不知道时请查看 DSH 配置或询问维护者。当前不会自动沿用聊天模型。

确认固定版本、源码来源及分析计划，勾选发送授权，再点击“开始执行 · 生成报告”。模型将收到本次差异、相关路径和所选源码内容，可能产生费用。每次点击都消耗本次确认，失败、取消或更改模型后必须重新勾选。

分析计划按文件和差异块自动分片，不设固定片数上限，逐片调用模型；无需另勾选规模开关，发送前仍须核对实际总字节、变更路径、源码文件和片数及多次调用费用。单片输入预算默认 24000，可在 4000–64000 字节间调整；它是含提示与 JSON 包装的保守字节估算，**不是 token 数，也不能保证适配所有模型**。修改预算后先“更新分析计划”，不会自动调用模型。总证据不受单片预算限制；单片提示和元数据无法装入预算时仍会拒绝规划，不静默截断，可提高预算或调整范围。进度只显示已完成片数，不将它当作耗时百分比。

可以取消任务。模型派发前已取消时不会启动模型入口；**已发送的请求不能保证撤回，是否停止及是否计费由模型服务决定**。离开面板或切换会话不会自动取消付费分析；结果仍归原会话。失败或取消后先只读核对后台状态，不能凭错误提示判定未执行或未计费；只有已确认停止且允许重试、预览仍有效时，才再次确认重试；宿主只复用同版本证据与分片内容、同计划、同提供方和同模型已经校验成功的分片，重试剩余片仍可能计费。更改模型或更新计划会清除已完成缓存，后续重新分析全部分片，不自动重试付费请求。模型已完成但响应丢失时，可用“恢复已完成报告”按原任务 ID 只读查询，不重新派发；缓存有 10 分钟和容量限制，不保证永久留存。结果尚未知时应先恢复或核查，不能把断线当作未计费。

### 报告中的对外接口变更

AI 报告要求独立列出 HTTP/RPC、公开函数/类/SDK、消息与协议契约的新增、删除、签名、参数、返回值、错误码和行为变化，给出 A/B 对比、兼容性、调用方迁移及接口测试建议，并引用文件/差异证据。内部函数不自动视为对外接口；对外性或旧契约未知时标为待确认。

模型必须返回规定的改动、接口、影响、QA、未知项五组结构化数据，结论引用本片真实证据 ID；程序检查格式与引用，再生成 Markdown。无效引用、自由 Markdown、截断输出或工具请求都会失败，不作为完整 AI 报告导出。报告附证据索引、分片与排除项，方便人工复核。SVN 属性或目录变化即使没有文本 diff，也会以范围证据列出；无法精确匹配到变更路径的块不按文件顺序猜测。范围证据不等于已读文件正文，也不能据此判断接口没有变化。

这是基于已提供证据的模型分析，不是完整 API 扫描或兼容性证明。**引用有效不等于结论正确，分片完成不等于每条证据被正确理解**；未发现变化不保证没有变化。历史接口分析可附带 A/B 固定版本的声明或协议文件，当前磁盘源码不能当作历史版本。未调用模型时接口章节明确标为尚未分析。

### 7. 下载并保留结果

点击“下载 .md 文件”。页面以纯文本展示结果，不执行其中的 HTML。导出时对标题、路径、限制说明及模型文本等不可信字段做 Markdown 转义，原始差异放在围栏内；外部阅读器与插件行为仍需分别核验，不把浏览器纯文本展示当作下载文件的安全证明。

报告不会自动写入项目，也不会随“保存配置”持久化。内存状态仅限当前插件实例，不提供跨刷新、宿主重启恢复或多个标签页之间的全局互斥。当前插件实例在内存中按会话和工作区保留最近结果；切回会话可查看旧报告，但不恢复快照或模型发送确认。当前展示和最近一份成功模型报告共同占用缓存。结果未知时的恢复任务 ID 也仅按会话保留在插件内存中，切回可继续查询；刷新或插件重载会丢失，恢复前会阻断新分析和更新。报告正文按最多 16 个会话保留，可能按会话数量淘汰，不设固定正文总字节上限；大报告更耗内存。未确认的任务身份不会因正文淘汰就视为已结束。明确“放弃恢复”只标记放弃，不解除结果未知的任务屏障；仍需后台明确停止或报告完成才能恢复新业务及安装。它不证明远端请求停止或未计费；**刷新、插件重载或更新前仍须下载**，不能把内存保留当作可靠归档。可显式清除当前结果。

## 更新插件

展开页首“插件版本与更新”，先下载报告、保存配置，等待当前任务结束，再检查更新。检查只请求 npm 元数据，不安装，不发送项目源码。

前后台一致且有更新版本时，勾选确认后才安装。安装使用 DSH 原生插件管理器，不自动重启，也不绕过兼容性或安全策略。

- **需要重启**：保存工作，手动完全退出并重新打开 DSH，再刷新页面。
- **已应用**：按宿主提示加载新版界面；若前后台仍不一致，手动重启。
- **结果未知**：安装可能仍在进行，到 DSH“插件”页面核查，不重复安装。
- **明确失败/取消**：按错误检查；业务操作可恢复，已有报告不会因解锁自动重扫而清空。

报告业务与安装在同一插件实例内互斥：活动任务或结果未知时先核对，不能切换会话来绕过；只读恢复和报告下载仍可用。更新期间和需重载/未知终态会锁住业务操作。控制器在当前插件实例内保留状态，切换会话不解除；刷新或插件重载不保证保留安装状态。此时仍应先核查宿主，不把锁消失当成安装完成。

## 限制与数据边界

| 项目 | 当前行为 |
| --- | --- |
| 自动发现 | 根目录和一级子文件夹；最多 500 项目、100000 目录，约 120 秒扫描预算；未覆盖会提示 |
| 单次比较 | 1–12 个项目，比较两个已保存版本的端点，不含未提交变化 |
| 补充源码 | 工作区支持文件或递归目录，固定版本仅文件；路径条目、文件数量和单文件大小不设固定规模上限；无 NUL，UTF-8 优先、失败后尝试 GB18030（兼容 GBK） |
| 源码目录展开 | 不设固定条目、目录和深度上限；跳过点前缀隐藏、敏感、依赖、构建、缓存路径、链接及非普通文件并显示排除计数；不按 Windows Hidden 属性筛选 |
| 总证据 | 不设固定总量、单命令证据输出（stdout）或分析片数上限；不等于无限资源，仍受可用内存、操作系统及工具限制 |
| 分批分析 | 单片输入预算 4000–64000 字节估算，非 token；不支持的模型需自行调整或缩小范围 |
| 读取失败 | 待附带文件无法读取、二进制或非法编码使整次采集失败，不静默截断；项目自动发现预算中断仍返回部分发现及提示 |
| 编码 | 源码整文件、差异按原始 LF 行优先严格 UTF-8，失败后尝试 GB18030（兼容 GBK）；元数据仍严格 UTF-8，不保证歧义或同行混合编码 |
| Git 读取 | 严格本地；缺少提交或文件对象时失败，不访问 promisor remote 补取对象 |
| Git 子模块 | 仅记录指针变化，不分析内部差异；LFS 引用不等于实际大文件内容 |
| 影响分析 | 不生成完整调用图，不自动执行测试，不保证识别跨项目关系 |

## 故障排查

| 现象 | 先检查什么 / 怎么处理 |
| --- | --- |
| 无“发布报告”入口 | 插件是否装在当前 profile、是否启用；保存工作后手动重启并刷新 |
| 界面新版，后台旧版 | 不要重复安装。保存配置、下载报告后完全退出并重开 DSH；刷新不能替代后台重载 |
| 后台连接失败、HTTP 404/405 | 先确认启用和版本；旧版路由故障可从 DSH 原生插件页升级，再手动重启。404/405 不是单一根因证明 |
| 未发现项目 | 确认工作区、项目是否处于一级目录、是否有 .git/.svn；嵌套或跳过目录手动添加 |
| 还出现“6 层 / 1500 目录”提示 | 这是旧后台行为，不是当前扫描限制；核对后台版本，重启后重新扫描 |
| 采集按钮不可用 | 后台验证需通过；选中 1–12 项，补齐版本，SVN 还需两侧分支 |
| 版本或对象不存在 / SVN 访问失败 | Git 引用和对象须完整保存在本地；缺对象时先在插件外补齐。SVN 核对分支、固定版本、授权、网络及读取权限 |
| 预览已过期或不可用 | 重新采集；10 分钟、缓存淘汰、后台重启或预览已消费均可能导致不可用 |
| 编码拒绝或正文乱码 | 先核对错误来自正文还是仍须 UTF-8 的路径/XML 元数据；正文已自动尝试 UTF-8 与 GB18030。含 NUL 或两者均非法会拒绝；已有乱码不会修复。检查原始编码与报告哈希，必要时在独立副本准备可比较文本，不直接修改业务历史来消除错误 |
| 敏感路径或系统资源不足 | 核对被拒路径或调整采集范围；当前不支持逐个排除某条变更路径，不要删除真实凭据来绕过检查 |
| 只有差异，没有 QA 建议 | 当前是本地证据报告；确认模型及发送授权后执行生成 |
| 更新被新包冷却期拒绝 | 遵守宿主/包管理器策略，等待或由管理员评估；插件不会自动降低安全策略 |
| 页面退出或白屏 | 不反复点击更新；记录前后台版本、发生时间、操作步骤和原始错误。此前反馈的直接原因尚未确定 |

反馈问题时附上插件与 DSH 版本、系统、阶段（扫描/采集/生成/更新）和脱敏错误。**不要上传完整源码、密钥或含凭据的日志。**
