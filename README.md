# DSH Code Report

DSH 多 Git / SVN 项目发布报告插件（0.1.0 首次分发版本）。

## 用途

在同一会话工作区内，指定多个项目各自的版本 A（基线）与 B（发布目标），采集端点差异；可选附带项目源码，再通过 DSH 已配置的模型生成一份中文 Markdown 发布报告。

报告包含：改动内容、直接与可能间接影响范围、跨项目关系、QA 测试建议（优先级、前置条件、操作步骤、预期结果）、未覆盖项和原始差异证据。模型输出需要人工复核，不代表测试已通过。

## 使用流程

1. 在 DSH 打开一个工作区会话，从左上侧功能区进入“发布报告”（与“VCS 变更”同级），打开配置页。
2. 点击“发现工作区项目”，或手动添加项目。路径必须相对于会话工作区，根目录填 .。
3. 每个项目填写版本 A / B。Git 可用本地分支、tag 或提交；采集时固定为完整 commit ID。SVN 仅允许固定数字 revision，B 不小于 A，且必须勾选历史仓库访问授权。
4. 可选逐行填写源码文件的工作区相对路径。它们来自当前工作区，不自动当作历史版本源码。
5. 点击“开始执行 · 采集差异”。进度条按实际采集完成的项目和源码文件显示计数。预览不调用模型；可直接下载本地证据报告。
6. 检查差异与源码范围，填写 DSH 中已配置的 provider / model ID。明确确认发送后，点击“开始执行 · 生成报告”。模型阶段显示不定进度条，不虚构百分比；完成、失败和取消均有明确状态。
7. 查看 Markdown 纯文本，点击“下载 .md 文件”，由浏览器保存。插件不会自动写入被分析的仓库。

## 数据与安全边界

- 仅执行 Git / SVN 读取操作，不 checkout、update、merge、修改索引或提交。Git 不 fetch；SVN 使用工作副本记录的仓库地址，可能访问网络。
- Git 两端先解析为 commit ID；SVN 使用 UUID、URL、固定 operative / peg revision 记录来源。
- 源码附带是显式文件选择，不是整仓上传、自动调用链检索或完整影响图。
- 当前工作区源码附带最多 20 个文件，每个最多 128 KiB，要求 UTF-8 文本；仓库最多 12 个。
- 证据 JSON 总量限制 1 MiB，单条 VCS 命令输出限制 4 MiB，单命令超时 60 秒，单 RPC 超时 240 秒；超限报错，不静默截断。
- 预览快照存储于宿主进程内存，10 分钟后不可用，模型分析成功后不可重复使用；分析失败可重试。重试可能重复产生模型费用。
- 模型只获得本次快照，不具备工具执行能力。界面以纯文本展示报告，不渲染不可信 HTML。导出 Markdown 仍需使用可信阅读器。
- 拦截常见凭据路径（如 .env、私钥）；这不是完整秘密扫描。提交到普通源码中的 token 或密码仍可能出现，发送前必须自行检查。
- 工作区路径由宿主 Session 提供；浏览器不能指定工作区外的根目录。相对路径与 realpath 检查拦截路径穿越和工作区外链接。

## 本地开发

要求 Node.js >= 22，Git；SVN 功能需要 svn，SVN 集成测试还需要 svnadmin。

~~~sh
npm ci --include=dev --ignore-scripts
npm run check
npm run verify:package
npm run test:install
~~~

包提供 DSH 服务端入口、客户端模块加载器产物和 Cordis 插件配置。客户端 React 由 DSH 提供。这里只构建开发项目，不自动安装到当前 DSH，不启动替代宿主，不重启 DSH。

CI 仅版本标签与手动触发；正式发布在四项平台测试通过后执行，先 npm 后 GitHub Release，复用同一安装包。需要配置仓库 Secret `NPM_AUTOMATION_TOKEN`。详见 [发布流程](<docs/RELEASING.md>)。

许可：非商业使用、学习、修改和分发；商业用途（含商业项目内部开发、测试、维护）须另行取得书面授权，详见 [许可证](<LICENSE>)。

## 当前限制 / 待验收

- 已实现 Git / SVN 端点差异采集；不提供提交日志归纳，不递归分析子模块、LFS 实体或二进制行为。
- Git 根目录必须位于会话工作区内；SVN 以选择的工作副本目录范围为准。
- 发现扫描最多 3 层、300 个目录；更深的项目可手动输入。扫描会跳过隐藏目录、node_modules、dist、build 和符号链接。
- 模型 ID 暂时手填，不自动读取当前 Agent 的模型，也不内置独立 API Key。
- 多仓库证据一次提交模型做联合分析，不自动分块；提供方上下文窗口不足会失败，需要缩小范围。
- QA 建议与影响推断没有静态调用图或自动证据一致性校验，不能当作穷尽覆盖结论。
- 尚未安装到正式 DSH，也未完成真实宿主浏览器交互和真实模型端到端验收。自动测试使用隔离 Git / SVN 仓库及模拟模型。

## 项目结构

- [宿主入口](<index.mjs>)：Session 绑定、预览与生成 RPC。
- [差异采集](<src/collect.mjs>)：Git / SVN 和显式源码快照。
- [报告分析](<src/report.mjs>)：模型调用与 Markdown 输出。
- [配置界面](<src/client.jsx>)：多项目版本配置、发送确认与下载。
- [自动化测试](<test/report.test.mjs>)：真实隔离仓库、安全边界、模拟模型。
