# DSH Code Report · 多项目发布报告

发布前，想知道“这次改了什么、会影响哪里、测试该测什么”？

DSH Code Report 是 **DeepSeek Harness（DSH）的插件**。你为每个 Git / SVN 项目填写旧版本和新版本，它会读取差异，再借助 AI 整理成一份中文报告，最后下载为 Markdown（.md）文件。

**可以同时比较多个项目，合并输出一份报告，不用逐个仓库手工整理。**

> 当前已发布 v0.3.1。自动化测试和安装包检查已通过；在真实 DSH 界面中完整操作、调用真实模型的验证尚未完成。建议先在独立测试环境试用，不要直接替换日常工作的插件环境。

## 能得到什么

- **改动内容**：按项目和功能整理本次版本变化。
- **影响范围**：哪些模块直接受影响，哪些地方可能需要关注。
- **QA 测试建议**：测试优先级、准备条件、操作步骤和预期结果。
- **待确认事项**：哪些结论证据不足，需要开发或测试人员补充确认。
- **原始差异**：保留分析依据，方便回查。

AI 的分析是建议，不是测试结果，也不是发布批准。报告仍需人工检查。

## 安装

需要先有可运行的 DSH。运行 DSH 的机器还需要 Node.js 22 或更新版本，以及你要使用的 Git 或 SVN 命令行工具；只比较 Git 项目时，不需要 SVN。

在终端执行下面的命令。**先将 <你的配置环境> 替换成当前 DSH 使用的 profile 名称**。profile 是保存 DSH 配置和插件的环境，不是左侧的工作区或会话名。安装命令需要机器上可以使用 pnpm。

~~~sh
dsh plugin --profile <你的配置环境> add @feng0531/dsh-code-report@0.3.1
~~~

例如，你使用的 profile 确实叫 desktop，才执行：

~~~sh
dsh plugin --profile desktop add @feng0531/dsh-code-report@0.3.1
~~~

安装会修改所选环境，请先备份配置。安装后由你自行重启 DSH，并刷新原来的页面。本项目发布新版本时，**不会自动安装、升级或重启你的 DSH**。

也可以从 [GitHub 发布页](https://github.com/f-e-n-g-0531/dsh-code-report/releases/tag/v0.3.1) 下载安装包。开发者不需要为了使用插件而下载源码、编译或运行测试。

## 更新插件

配置页上方有“插件更新”区域，会分别显示当前界面和后台的版本。

1. 先下载需要保留的报告，等当前分析结束。
2. 点击 **“检查更新”**。这只查询 npm 上的最新正式版本，不会安装，也不会发送项目源码。
3. 如果有新版，先查看版本说明，备份 DSH 配置，再勾选确认，点击 **“更新到该版本”**。
4. 等待安装结果。需要重启时，页面会明确提示你**手动重启 DSH，再刷新页面**；如果宿主报告已经应用，则按提示刷新页面。

更新使用 DSH 自带的插件管理器，安装到当前配置环境，不会自行执行重启。**当前 DSH 更新已安装插件通常仍需重启，前后端代码分开不等于后台可以热更新。**

如果提示结果未知，请到 DSH“插件”页面检查，不要反复点击更新；如果界面和后台版本不一致，先保存报告，再刷新，仍不一致时手动重启。旧版没有更新按钮时，需要先按上面的安装方法升级一次。

## 第一次使用

### 1. 打开配置页

在 DSH 中打开一个有工作目录的会话，点击左上侧功能区的 **“发布报告”**，与“VCS 变更”同级。

如果同时比较多个项目，请把会话工作目录设为这些项目的共同上级目录。

### 2. 选择项目，填写两个版本

打开页面后会自动查找当前工作区下的 Git / SVN 项目。勾选“纳入报告”选择本次要比较的项目；可以点击“重新扫描项目”，也可以手动补充。重新扫描会保留已填写的版本和勾选状态，新发现的项目默认不勾选，一次最多纳入 12 项。每个项目的 A、B 两侧分别填写：

| 配置项 | 怎么填 |
| --- | --- |
| 项目路径 | 相对于当前工作目录的文件夹名称；项目就是工作目录本身时填 . |
| VCS | 选择 Git 或 SVN，也就是项目使用的版本管理工具 |
| 版本 A | 上一次发布的版本，作为比较起点 |
| 版本 B | 这次准备发布的版本，作为比较终点 |

**例如**，你的工作目录是 G:/work，下面有 client 和 server 两个 Git 项目：

| 项目路径 | VCS | 版本 A | 版本 B |
| --- | --- | --- | --- |
| client | Git | v1.0.0 | v1.1.0 |
| server | Git | v2.3.0 | v2.4.0 |

这里的版本名称只是例子，需要换成项目中实际存在的版本。

- **Git**：可以填标签、分支名或提交编号。插件只读取本地已有版本，不会自动从远端下载。
- **SVN**：A、B 两侧都要填写“分支路径”和“r 版本”。例如 A 为 `trunk` + `r1200`，B 为 `branches/release` + `r1250`，也可以比较同一分支的两个版本。版本填 `r1250` 或 `1250` 均可。分支路径相对于 SVN 仓库根目录，不是本地文件夹，也不能填写任意 URL；填 `.` 表示当前工作副本对应的仓库路径。自动发现会尝试预填当前分支。还要勾选允许读取 SVN 历史版本的选项，因为这可能连接仓库服务器。

### 3. 按需附带源码

如果差异本身不足以说明用途，可以补充相关源码，例如调用方、配置文件或公共接口。

在“附带项目源码”中每行填一个文件路径，路径同样相对于当前工作目录。它可以来自另一个项目，不必是本次比较的仓库。

插件只读取你选中的文件，不会自动上传整个项目。**补充文件取自你现在磁盘上的内容，不一定等于版本 A 或 B 中的内容。**

### 4. 开始采集并检查范围

点击 **“开始执行 · 采集差异”**。

页面会显示正在处理的项目，以及已经完成的项目和源码文件数量。完成后，你可以查看比较范围与原始差异。

**这一步不会调用 AI。** 如果只需要一份差异记录，现在就可以下载报告；它还不包含 AI 整理的影响分析和测试建议。

### 5. 让 AI 整理报告

在预览下方填写 DSH 中已经配置好的 **提供方 ID** 和 **模型 ID**：前者标识使用哪一个模型服务，后者标识具体模型。当前版本需要手动填写，不会自动沿用聊天模型，也不需要在插件中另填 API Key。若不知道 ID，请向配置 DSH 的人确认，不要凭显示名称猜测。

确认范围后，勾选发送确认，再点击 **“开始执行 · 生成报告”**。

此时会把本次差异和所选源码交给指定模型，可能产生模型调用费用。模型分析时显示动态进度条，不显示无法准确计算的百分比。执行期间可以点击“取消”。

### 6. 下载报告

生成完成后，点击 **“下载 .md 文件”**，由浏览器保存。

.md 是 Markdown 文本文件，可用文本编辑器打开，也可以用支持 Markdown 的工具阅读或继续编辑。插件不会自动把报告写进你的项目。

## 使用前需要知道

- **不会修改项目代码或切换版本**：比较的是 A、B 两个已保存版本，未提交的修改不计入差异；你主动附带的源码文件除外。
- **发送前请检查敏感内容**：插件会拦截部分常见凭据文件，但不能保证识别源码里所有密码、密钥和私人信息。
- **不是完整的影响分析工具**：不会自动追踪整个项目的调用关系；未提供的代码和跨项目关系，AI 可能无法判断。
- **不分析图片、二进制内容，以及 Git 子模块内部的代码变化**。大文件引用也不等于实际大文件内容。
- **目前有大小限制**：一次最多 12 个项目；附带源码最多 20 个 UTF-8 文本文件，每个不超过 128 KiB（约 128 KB）。差异与补充源码合计约 1 MiB，超出时会报错，不会悄悄省略内容。
- **预览有效期为 10 分钟**：过期后重新采集。模型服务可接受的输入大小也有限，输入过大时需要减少项目或附带文件。重试分析可能再次计费。

## 常见问题

**检查更新提示 HTTP 405，后台版本一直读取中？**

0.2.0 至 0.3.0 的后台入口遗漏了路由所需依赖，可能导致界面已加载、后台不可用。请通过 DSH 自带“插件”页面或上面的安装命令升级到 0.3.1 或更新版本，再手动重启 DSH 并刷新页面。此时不能依赖故障插件自己的更新按钮完成修复。


**看不到“发布报告”入口？**

确认插件安装到了当前 DSH 使用的配置环境，然后自行重启 DSH、刷新页面。只下载源码或安装到另一个环境，不会让当前页面出现入口。

**界面已经是新版本，后台仍连接失败？**

界面版本只说明浏览器加载了新文件，不表示 DSH 后台已重载。安装或更新后，请保存工作，手动完全退出并重新打开 DSH；只刷新页面不会重载后台。如果仍失败，请在 DSH“插件”页面确认插件已启用，并保留页面给出的原始错误。

**没有发现我的项目？**

自动查找优先检查工作区根目录及浅层项目，最多检查 6 层、1500 个目录，跳过隐藏目录、构建缓存和链接目录，可能漏掉更深的项目。扫描失败不等于发现了 0 个项目：页面会分别显示扫描中、失败、取消、完成，并保留限制提示。可以手动填写项目路径。Git 项目要选仓库根目录；工作目录以外的项目不能直接读取。

**开始按钮点不了？**

先选中至少一个项目，并为它填写版本 A 和 B。生成 AI 报告前，还需要填写模型信息并勾选发送确认。正在执行时不能重复开始。

**提示版本不存在？**

检查项目路径和版本拼写。Git 版本需要已经存在于本地；SVN 需要能访问仓库，并有读取对应版本的权限。

**报告只有差异，没有影响范围或 QA 建议？**

你下载的是采集后的本地差异报告。继续确认模型信息并执行“生成报告”，才会得到 AI 分析。
